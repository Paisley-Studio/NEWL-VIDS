# Quick reference guide

The essential tasks in the NEWL AFRICA management platform, by role. Each item names the lesson that demonstrates it.

## Everyone

- **Sign in** on the tab that matches your role (Admin or Team Leader). Usernames without “@” become `username@newl.africa`. *(Lesson 01)*
- **Notifications:** bell icon or sidebar. Opening a notification marks it read and opens the related project. *(Lesson 05)*
- **Sign out** with the button beside your name, especially on shared devices. *(Lesson 01)*
- Never share passwords, credentials, configuration values or screenshots containing them. *(Lesson 06)*

## Administrators

| Task | Where | Notes |
|---|---|---|
| Create a project | Home or Projects → **New Project** | Name and SMP required. Budget becomes the allocated budget. *(L02)* |
| Add a team leader | Team Leaders → **Add Team Leader** | Password is generated and sent by SMS. You confirm your password, then sign back in once. *(L02)* |
| Assign / reassign projects | Team leader card → **Assign Projects**, or project **Edit** | One team leader per project. *(L02)* |
| Record expenditure | Project → **Financials** tab → **Add** | Item, amount, date, receipt/reference. *(L04)* |
| Decide a fund request | Financials → Pending Fund Requests | **Approve** (amount can be adjusted) or **Decline** (optional reason). *(L04)* |
| Approve a completed project | Project marked *pending approval* → **Approve** or **Send Back** | Send Back returns it to Active with a reason. *(L02)* |
| SMS settings | Settings → SMS Notifications | Dry-run for testing; per-event switches affect SMS only; saved **per browser**. *(L05)* |
| Review activity | **Audit Log** | Latest 100 actions: time, user, action, details. *(L05)* |
| Remove a leaver | Delete the team leader | Projects become unassigned. Ask the technical team to remove the Firebase sign-in account. *(L06)* |

## Team leaders

| Task | Where | Notes |
|---|---|---|
| See your work | **My Projects** | Only projects assigned to you. *(L03)* |
| Add a casual worker | My Casuals or project **Casuals** tab → **Add Casual** | Name and phone required; worker and admin get an SMS. *(L03)* |
| Submit a daily log | **Submit Daily Log** | Project, date, hours, work done (required), materials, casuals present. Logs cannot be edited — check before submitting. *(L03)* |
| Request additional funds | **Fund Requests** → **Request Funds** | Amount and a specific reason. *(L04)* |
| Finish a project | Project → **Mark Complete** | Moves to Pending Approval. *(L03)* |

## Reading the figures

- **Remaining = Budget − Expenditure − Approved additional funds.** Pending requests are shown separately and are not deducted. *(L04)*
- **Progress bar** = activity indicator based on logs submitted (max 90% while active; 100% only after approval). *(L02)*
- **Used %** turns orange above 80% and red above 100%. *(L04)*
- Figures and logs summarise what was entered; they do not independently verify spending or site work. *(L03, L04)*

## Questions for Board oversight *(L06)*

1. Are projects reporting regularly, or have their logs gone quiet?
2. How much of each budget is used, and how much remains?
3. How often are additional funds requested, why, and how were they decided?
4. Does the audit trail show the expected people taking the expected actions?
